# 药膳厨房经营模拟游戏 — 设计文档

## 一、游戏概述

**类型**：2D 经营模拟 / 休闲解谜  
**引擎**：Godot 4.x（GDScript）  
**视角**：2D 俯视或侧视  
**风格**：国风 / 水墨插画风

玩家经营一家以传统药膳为特色的小铺子，根据客人的需求（普通点菜、生病调理、特殊菜品请求）进行烹饪，提升店铺评价，解锁更多食谱，扩大客源。

---

## 二、核心玩法流程

### 流程 A：客人看菜单点菜（常规流程）
```
客人进店 → 查看菜单 → 选择菜品 → 玩家进入烹饪界面
→ 选择食材 / 火候 / 时间 → 制作完成
→ 成功：增加客源 + 评价 ｜ 失败：失去客源
```

### 流程 B：客人生病（症状调理流程）
```
客人进店并表现症状（头痛/乏力/失眠等）
→ 玩家通过对话询问症状
→ 系统提示可用药膳候选
→ 玩家选择推荐药膳
  → 对症：进入烹饪流程 → 客人康复 → 提升评价 + 可能解锁新食谱
  → 不对症：推荐失败 → 失去客源
```

### 流程 C：客人请求特殊菜品
```
客人提出菜单上不存在的菜品
→ 系统提示"前往商店购买对应食谱"
→ 玩家前往商店购买
→ 返回烹饪界面完成制作
  → 成功：增加评价 + 解锁新食材或技能
```

## 四、核心系统设计

### 4.1 烹饪系统

#### 总体流程

```
选择食材（静态选择）
  → 进入力度条小游戏（2~3 轮，对应不同烹饪步骤）
	→ 每轮点击判定得分
  → 汇总所有轮次得分 → 出锅评级
```

#### 力度条小游戏机制

界面参考：锅具居中展示，锅下方有一个**半弧形力度条**，指针从弧形一端向另一端来回摆动，玩家点击屏幕/按键时，根据指针所在区域判定结果。

**弧形区域划分（从中心向两侧）：**

```
[  错误区  |  一般区  | 良好区 |【完美区】| 良好区 |  一般区  |  错误区  ]
```

| 区域 | 得分 | 视觉颜色 |
|------|------|---------|
| 完美区（中心黄色窄带） | 100 | 金黄色 |
| 良好区 | 70 | 橙色 |
| 一般区 | 40 | 灰色 |
| 错误区 | 0 | 红色 |

**每轮参数（菜谱配置）：**
```
CookingStep {
  step_name: String        # 步骤名（如"下锅"、"翻炒"、"出锅"）
  needle_speed: float      # 指针摆动速度（难度）
  perfect_zone_size: float # 完美区大小（0~1，越小越难）
  time_limit: float        # 本轮限时（秒），超时自动判 0 分
}
```

**轮次数量与难度：**
- 新手期菜谱：2 轮，指针速度慢，完美区大
- 成长期菜谱：2~3 轮，速度中等
- 精通期菜谱：3 轮，速度快，完美区极小

#### 最终评级

```
总分 = 所有轮次得分的平均值

≥ 90 → 完美（★★★）：额外评价加成
≥ 70 → 成功（★★☆）：正常结算
≥ 40 → 一般（★☆☆）：减少收益
 < 40 → 失败（☆☆☆）：扣除评价
```

#### 菜谱数据结构

```
Recipe {
  id: String
  name: String
  ingredients: Array[String]       # 所需食材 id 列表
  cooking_method: String           # 炒/炖/蒸/煮（展示用，不影响判定）
  steps: Array[CookingStep]        # 力度条轮次配置
  effects: Array[String]           # 药膳功效标签
  unlock_condition: String         # 解锁条件
}
```

### 4.2 客人系统

```
Customer {
  type: Enum           # normal / sick / special
  patience: float      # 等待耐心值（倒计时）
  symptoms: Array      # 症状列表（sick 类型）
  request: String      # 特殊请求（special 类型）
  satisfaction: int    # 满意度 0~100
}
```

客人生成规则：
- 每日客人数量 = 基础值 + floor(评价/10)
- 客人类型概率：normal 60%，sick 25%，special 15%
- 评价越高，special 客人比例上升

### 4.3 每日推荐机制

- 系统每天随机选取 1 道药膳作为"今日推荐"
- 推荐菜品的烹饪成功率加成 +10%
- 客人点该菜品的概率提升 30%
- 成功制作推荐菜品额外获得评价 +5

### 4.4 评价与客源系统

| 事件 | 评价变化 | 客源变化 |
|------|---------|---------|
| 烹饪完美（★★★） | +5 | +3 |
| 烹饪成功（★★☆） | +3 | +2 |
| 烹饪一般（★☆☆） | +1 | +1 |
| 烹饪失败（☆☆☆） | -2 | -1 |
| 对症调理成功 | +5 | +3 |
| 推荐失败 | -3 | -2 |
| 客人等待超时 | -1 | -1 |

评价阈值解锁：
- 评价 ≥20：解锁"商店扩展区"
- 评价 ≥50：解锁"高级食谱"
- 评价 ≥100：解锁"特殊食材"

### 4.5 存档系统

自动存档（每日结束时），支持手动存档。  
存档内容：当前评价、客源数、金币、已解锁食谱、仓库食材、已完成事件。

## 六、进度与解锁计划

| 阶段 | 解锁内容 |
|------|---------|
| 新手期（评价0~20） | 基础菜单5道、仓库10格、商店基础区 |
| 成长期（评价20~60） | 菜单扩展至15道、仓库20格、对话选项增加 |
| 精通期（评价60~100+） | 全菜单解锁、高级食材、特殊客人事件 |

## 八、美术风格指引

- **整体风格**：国风水墨插画，暖色调（米黄、朱红、墨绿）
- **UI 风格**：仿古木质边框、毛笔字体、印章元素
- **客人设计**：简笔人物，不同服饰区分身份
- **食材图标**：手绘风格小图标，64×64px
- **场景**：店铺内景（柜台、灶台、货架），静态背景 + 动态元素
